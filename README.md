# F.R.I.D.A.Y.

**ИИ-система разведки и подготовки персонального аутрича для юридического рынка России**  
*(адаптация каркаса [Harvey](https://github.com/ethanplusai/harvey) под экосистему Яндекса, 2ГИС, реестры адвокатов, ФЗ-38 «О рекламе» и ст. 17 КПЭА)*

---

## Зачем и чем отличается от Harvey

Оригинальный Harvey создан под рынок США: холодные email-рассылки по правилам CAN-SPAM через Gmail/Instantly, поиск через Google/DataForSEO и англоязычные должности. Для российского **бюро юридического трафика** (привлечение доверителей для адвокатов, адвокатских бюро и коллегий) такой подход не подходит ни юридически, ни репутационно:

1. **Закон (ст. 18 и ст. 5 ФЗ-38 «О рекламе» + ст. 17 КПЭА).** Автоматическая холодная рассылка без предварительного согласия адресата в РФ упирается в ст. 18 ФЗ «О рекламе», а один спамный заход в консервативной адвокатской среде бьёт по репутации. Поэтому в F.R.I.D.A.Y. **автоматическая отправка писем вырезана архитектурно** — система работает строго в контуре **«Разведка → Профилирование → Поиск ЛПР → Досье и черновик → Комплаенс-фильтр → Ручной заход человеком»** (Telegram, TenChat, личное обращение).
2. **Российские источники и сигналы.** Вместо Google Ads и Meta Pixel система собирает сигналы по **выдаче Яндекса (позиции 11–30)**, карточкам в **Яндекс Картах** и **2ГИС**, **реестрам адвокатов регионов / Минюста РФ**, проверяет наличие **Яндекс.Метрики**, **Яндекс.Директа / Calltouch / Roistat**, отдельных посадочных страниц под специализации, платформ **Tilda / 1С-Битрикс / Битрикс24 / amoCRM**, а также находит рискованные для **ст. 17 КПЭА** формулировки прямо на сайте практики.
3. **Русский язык и адвокатская специфика.** Распознавание полных русских ФИО с отчествами (`Волков Алексей Сергеевич` / `Алексей Сергеевич Волков`), российских ролей ЛПР (*Управляющий партнёр, Председатель коллегии, Старший партнёр, Учредитель адвокатского кабинета, Руководитель практики*), корректное обращение на «вы» по Имени-Отчеству и жёсткий фильтр против нейросетевых штампов («доброго времени суток», «точки роста», «гарантируем поток заявок»).

## Что сохранено из архитектуры Harvey

- **Хранение фактов как наблюдений (`observations` + `signal_codes` + SQLite-триггер).** Каждый сигнал о практике — это строка с `confidence`, датой и ссылкой-доказательством (`evidence_url`), а не жёсткая колонка БД. В сбор идут только сигналы, явно подтверждённые человеком (`status = 'confirmed'`).
- **Независимые стадии пайплайна через SQLite (WAL).** Стадии `discover`, `import`, `profile`, `scout` и `draft` не связаны списками в памяти — каждая берёт из базы то, что ещё не обработано.
- **Защита от Prompt Injection (`<untrusted>`).** Весь текст с внешних сайтов и справочников оборачивается в изолированные блоки `<untrusted>`, а вызовы Claude CLI выполняются без инструментов (`--tools ""`, `--safe-mode`).
- **Детерминированный комплаенс-фильтр (`friday/gate.py`).** Каждый черновик проверяется Python-кодом на отсутствие гарантий результата (ст. 5 ФЗ-38), нарушений ст. 17 КПЭА (предложения накрутки отзывов, сравнения с другими адвокатами), стоп-листа (`do_not_contact`, включая кириллические домены `.рф` и `@telegram`) и спам-клише.

## Мульти-провайдерный «Мозг» (`brain.provider`): не только Claude

В `friday.yaml` (или флагом `--provider`) поддерживаются 4 варианта аналитического движка:

1. **`claude` (по умолчанию, как у Harvey)** — работает через локальный `claude` CLI по подписке Claude Pro/Max в изолированном headless-режиме без дополнительных расходов на API.
2. **`agent` (работа на базе самого ИИ-агента: Arena.ai, Cursor, Windsurf, Claude Code)** — Python бесплатно собирает все сигналы с сайтов и складывает готовые пакеты задач в `data/agent_tasks/` (`friday tasks list`). ИИ-агент рабочей среды сам читает собранные факты, ставит оценки, пишет черновики и применяет их через `friday tasks apply <id>` с проверкой через `gate.py`. Не требует вообще никаких ключей и подписок!
3. **`openai_compatible` (любой внешний или локальный API)** — работает с OpenRouter, DeepSeek, Qwen, локальным Ollama / vLLM, а также OpenAI-совместимыми шлюзами к российским моделям (YandexGPT, GigaChat) через `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` в `.env`.
4. **`template` (детерминированный режим без LLM)** — мгновенно считает Fit Score (0–100) по формуле и собирает аккуратное досье и каркас сообщения строго по фактам без нейросети.

## Быстрый старт

```bash
# 1. Установка в виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# 2. Настройка под своё бюро (локальный файл не попадает в Git)
cp friday.yaml friday.local.yaml
cp .env.example .env

# 3. Подтверждение бесплатных сигналов сбора
friday signals --confirm free

# 4. Загрузка списка практик (или запуск поиска)
friday import my_list.csv
# либо: friday discover --provider twogis --query "коллегия адвокатов" --city "Екатеринбург"

# 5. Бесплатное HTTP-профилирование сайтов практик (Метрика, Директ, КПЭА, ФИО ЛПР)
friday profile

# 6. Оценка и генерация персональных черновиков + проверка ФЗ-38 и КПЭА
friday scout
friday draft

# 7. Выгрузка в CSV для русского Excel и в Markdown-тетрадь досье
friday export --out prospects.csv --dossiers dossiers.md --excel-ru

# 8. Или откройте удобную веб-панель управления
friday dashboard
```
